# TrustSci-Agent 项目交接资料与 GitHub 安全快照设计

## 1. 背景

当前两位新成员尚未全面掌握 TrustSci-Agent 的完成情况、整体架构、代码运行流程、输入输出、模型与算法、已有运行结果，以及后续需要完善的内容。现有仓库包含 README、PRD、Sprint 计划、架构/API 文档、源码、测试、运行数据和演示材料，但信息分散，部分历史交接说明已落后于当前代码。

本轮只处理当前目录 `TrustSci-Agent_v3(完成第五步)`，不讨论或比较其他项目目录。交付物用于新成员接手，并为后续制作 PPT 和技术文档提供可信素材。本轮不直接制作 PPT 或 Word 文档。

## 2. 目标与非目标

### 2.1 目标

1. 建立一个以根目录 README 为入口的中文模块化交接资料包。
2. 用当前代码、测试和代表性运行结果核验项目完成度，避免照抄过时计划。
3. 解释系统架构、任务运行链路、输入输出、模型算法、代码文件和环境配置。
4. 明确真实能力、演示能力、确定性降级逻辑、合成数据和待完善事项的边界。
5. 为两位新成员给出可执行的后续分工建议，并提供 PPT 页级素材提纲。
6. 将当前安全、可复现的完整项目快照提交并推送到新分支 `codex/project-handover-docs`。

### 2.2 非目标

1. 不修改科研工作流功能或新增业务能力。
2. 不制作最终 PPT、Word 技术文档或比赛申报材料。
3. 不合并或直接推送 `main`。
4. 不上传本地密钥、完整 LLM 调用日志、大量运行缓存或无必要的构建中间产物。
5. 不把合成地震数据或冻结演示结果描述为真实数据实验结论。

## 3. 资料包结构

根目录 `README.md` 是唯一总入口，用一页内容回答项目定位、当前状态、快速启动和后续阅读路径。详细资料位于 `docs/onboarding/`：

```text
docs/onboarding/
├── README.md                  # 新成员阅读顺序与导航
├── 01_PROJECT_STATUS.md       # 当前完成情况、阶段结论、已知限制
├── 02_ARCHITECTURE.md         # 前后端、浏览器服务、数据与智能体架构
├── 03_RUNTIME_FLOW.md         # 从用户输入到报告输出的代码运行流程
├── 04_INPUT_OUTPUT.md         # 输入字段、数据来源、中间产物和最终输出
├── 05_MODELS_ALGORITHMS.md    # Qwen、LangGraph、多智能体及实验算法
├── 06_RESULTS_EVIDENCE.md     # 测试、代表性结果和结果可信边界
├── 07_SETUP_GUIDE.md          # 环境、依赖、启动、检查和常见问题
├── 08_CODEBASE_MAP.md         # 关键目录、文件职责和推荐阅读顺序
├── 09_NEXT_WORK.md            # 待完善内容、优先级和成员分工建议
├── 10_PPT_SOURCE_OUTLINE.md   # 后续 PPT 的页级素材提纲
└── 11_GITHUB_CONTENTS.md      # 上传、排除和敏感信息说明
```

已有 `docs/API.md`、`docs/ARCHITECTURE.md`、PRD、Sprint 计划和演示材料继续保留。新资料通过链接引用，并修正明显过时的入口信息，不重复维护两套互相冲突的细节。

## 4. 事实来源与完成度口径

事实来源按以下顺序取舍：

1. 当前可执行代码和接口；
2. 本轮重新运行的测试与验证；
3. 已保存且可识别来源的运行产物；
4. 最新设计说明；
5. 旧 PRD、Sprint 计划和历史交接记录。

功能完成度采用四级状态：

- **已完成并验证**：代码存在，且测试或代表性运行通过。
- **已实现待复验**：代码存在，但本轮无法或尚未重新运行确认。
- **部分完成**：主体能力存在，但仍依赖演示数据、降级逻辑或存在明显闭环缺口。
- **未完成/后续任务**：只有计划、占位或尚未形成可用闭环。

文档必须显式区分真实 Qwen 调用和无密钥 fallback、真实文献检索和本地演示数据、AI 生成实验代码和固定执行框架、真实运行记录和冻结展示结果。任何测试数量、运行指标、模型名称和服务地址均在编写时重新核验，不沿用未经复验的历史数字。

## 5. 架构与运行链路表达

交接资料按服务、编排、智能体、工具、存储和实验六层解释项目：

- Next.js 前端负责研究任务配置、执行状态和结果工作台。
- FastAPI 后端提供运行、数据、浏览器和系统接口。
- LangGraph/Classic 工作流负责节点编排、分支、循环、恢复和人工操作。
- 多智能体负责规划、文献、证据、假设、批判、baseline、代码、结果和报告等科研任务。
- 浏览器工作进程、文献客户端、引用核验器和安全执行器提供外部工具能力。
- 本地数据目录保存运行状态、证据、报告、审计日志和可恢复工作区。
- 受控地震实验 harness 使用固定数据、baseline、测试、训练和指标协议，只允许生成模型实现进入隔离目录执行。

主运行链路按实际代码入口追踪：

```text
前端提交研究任务
→ FastAPI 创建并启动 Run
→ LangGraph 或 Classic 编排
→ 意图识别与研究规划
→ 文献检索、引用核验与证据账本
→ 假设生成、竞技和新颖性判断
→ baseline 发现、验证与质量门
→ 实验设计、代码生成和受控执行
→ 结果分析、消融和反馈循环
→ 报告生成、审计、导出与工作区保存
```

分支、重试、跳过、暂停、恢复、实验重设计和假设回退单独说明，避免把图编排误写成单向流水线。

## 6. 模型、算法与文件说明

模型与算法文档分别说明：

- 阿里云百炼 Qwen 的兼容接口、配置、审计与确定性 fallback；
- LangChain LCEL 适配层和 LangGraph 状态图编排；
- 多智能体角色、输入、输出和依赖；
- 文献排序、引用/主张核验、证据选择和 baseline 质量规则；
- 地震合成数据的类别、规模、划分和真实性限制；
- 固定传统机器学习 baseline、AI 生成模型、特征工程和公平比较协议；
- accuracy、macro-F1、per-class F1 等指标；
- 代码静态检查、脚本白名单、环境变量隔离、超时和修复轮次；
- 仓库是否包含预训练权重，以及模型文件在运行时如何生成或保存。

代码地图为每个关键目录和入口文件提供“职责、被谁调用、依赖谁、建议阅读顺序”，使新成员无需遍历全部文件即可理解核心闭环。

## 7. GitHub 快照与安全边界

目标分支为 `codex/project-handover-docs`。该分支从当前本地 HEAD 创建，保留当前工作区已有修改；不改写或合并 `main`。

上传范围包括有效源码、测试、受控实验 harness、Docker 与依赖配置、`.env.example`、PRD/Sprint/架构/API 文档、新交接资料、必要样例数据、少量脱敏代表性结果，以及正式演示材料。

默认排除：

- `.env`、API Key、Token、凭据和本机私有路径；
- `.venv`、`node_modules`、`.next`、`__pycache__`、pytest 缓存和 `tsconfig.tsbuildinfo`；
- `.pptx-build` 及多版本构建中间文件；
- 大量 `data/workspace/run_*`、完整 LLM 调用日志、浏览器 trace、临时截图和缓存；
- `tmp/`、`logs/` 和本地工具缓存；
- 无必要的大文件和无法确认授权或隐私边界的数据。

代表性结果优先整理为脱敏摘要，而不是直接提交完整原始运行目录。提交前执行敏感信息扫描、文件体积检查、`.gitignore` 检查和待提交清单复核。

实现阶段计划拆分为两个提交：

1. 安全源码快照与配置整理；
2. 新成员交接资料、代表性结果和索引。

设计说明作为前置独立提交。最终仅推送新分支。

## 8. 验证与读者测试

验证分四层：

1. **代码层**：运行后端测试、前端测试/构建和实验 harness 验证。
2. **配置层**：检查 Docker Compose、依赖清单、环境变量示例和环境检查脚本。
3. **内容层**：核对文档中的接口、路径、模型名称、测试数量和运行指标。
4. **读者层**：使用不带当前对话背景的独立审阅实例，只提供交接文档，测试其能否回答项目目标、完成度、启动方式、运行流程、输入输出、模型算法、结果真实性、后续分工、模型文件和 GitHub 内容边界。

读者测试发现的歧义必须回写到相应文档。只有测试通过、敏感扫描无未处理问题、待提交清单合理并成功推送目标分支，才视为本轮完成。

## 9. 风险与控制

- **历史文档过时**：以当前代码和复验结果为准，并在状态文档中标记历史资料用途。
- **脏工作区误提交**：分阶段暂存和逐项检查，不使用一次性全量提交。
- **敏感信息泄露**：扩大 `.gitignore`，扫描密钥模式和本机路径，代表性结果采用摘要。
- **演示结果被误解**：在状态、算法和结果文档中重复标注合成数据与冻结演示边界。
- **文档与代码不一致**：在实现结束前再次从入口文件、路由和测试输出回填事实。
- **GitHub 推送失败**：先验证远程和认证；若认证不可用，保留完整本地提交并报告唯一阻塞点。

## 10. 验收标准

1. 新成员可从根 README 在 10 分钟内找到项目状态、启动方式和推荐阅读路径。
2. 模块化资料覆盖完成度、架构、运行流程、输入输出、模型算法、结果、环境、文件地图、后续任务、PPT 素材和 GitHub 边界。
3. 所有关键事实有代码、测试或运行产物依据，限制条件表达清楚。
4. 完整安全项目快照分阶段提交到 `codex/project-handover-docs`。
5. 验证和独立读者测试通过，分支成功推送到现有 GitHub 远程。

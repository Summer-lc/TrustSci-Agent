# TrustSci-Agent 三栏科研工作台与运行韧性设计

## 1. 背景与目标

TrustSci-Agent 已具备文献检索、证据核验、假设竞技、可信 baseline 接入、代码实验、实验重设计和报告生成等主要科研闭环。本轮不重写科研工作流，而是在现有 FastAPI、Next.js 和浏览器抓取服务基础上，完善端到端使用体验。

本轮目标是：

- 将前端重构为左侧科研对话、中间研究流程、右侧文献原文的三栏工作台。
- 让用户通过对话框直接创建并执行任务，不再进行二次确认。
- 为工作流步骤提供统一状态、一次自动重试、人工重新执行和受控跳过能力。
- 允许用户从历史任务中主动选择并恢复运行。
- 文献原文优先显示 PDF；没有 PDF 时自动抓取论文网页并展示快照和原始链接。
- 保持现有可信闭环：baseline 仅由人工上传或 AI 生成，实验结果较差时进入实验重设计循环。

## 2. 实施策略

采用渐进式闭环重构。保留现有工作流主体和数据结构，在后端增加统一运行控制接口，在前端重组信息架构和交互。新增接口保持清晰边界，使未来可以升级为后台任务队列和事件流，而本轮不引入额外基础设施。

不采用以下方案：

- 仅改前端：无法可靠处理刷新、恢复和后端步骤失败。
- 全量任务事件系统重构：当前工作量与迁移风险过高，不符合本轮渐进完善目标。

## 3. 前端信息架构

### 3.1 左栏：科研对话

左栏承担任务入口、过程反馈和失败处理：

- 输入研究问题和必要参数后直接创建并启动任务。
- 以结构化消息显示当前动作、完成摘要、警告和错误。
- 当步骤进入等待处理状态时，在对应消息中显示“重新执行”和按规则开放的“跳过”操作。
- 提供历史任务入口。用户选择任务后再恢复，不自动打开最近一次未完成任务。
- 显示当前任务标识、研究模式和总体状态，避免用户混淆不同运行。

### 3.2 中栏：研究流程

中栏按科研阶段组织现有面板：

1. 研究目标与检索计划。
2. 文献检索与证据核验。
3. 假设生成与多智能体评审。
4. 人工上传或 AI 生成 baseline。
5. 实验设计、代码执行与结果评估。
6. 实验效果不佳时的重新设计与再次执行。
7. 报告生成、声明核验与导出。

每个阶段显示状态、摘要、耗时或尝试次数，以及该阶段最重要的产物。用户点击阶段后才展开详细内容，避免现有面板一次性堆叠。实验重设计需显示循环轮次和每轮结果。

### 3.3 右栏：文献原文

右栏随中栏选择的文献联动：

1. 有可访问 PDF 时，优先嵌入 PDF。
2. 没有 PDF 时，自动请求 browser-worker 抓取论文页面。
3. 抓取成功时显示网页快照、标题、摘要和原始链接。
4. 抓取失败时仍显示已有元数据和原始链接，并提供重新抓取操作。

网页抓取结果按论文标识和源地址缓存，避免每次切换文献都重复抓取。

### 3.4 响应式行为

- 宽屏使用固定三栏布局。
- 中等宽度下右栏变为可收起抽屉。
- 窄屏按“对话—流程—文献”标签页切换，确保对话和当前步骤始终可用。
- 三栏分别拥有独立滚动区域，避免整页滚动导致上下文丢失。

## 4. 后端运行控制

### 4.1 统一步骤状态

工作流步骤使用以下状态：

- `pending`：等待执行。
- `running`：正在执行。
- `completed`：执行完成。
- `retrying`：首次失败后自动重试。
- `waiting_action`：重试仍失败，等待人工处理。
- `skipped`：按规则主动跳过。
- `failed`：不可继续的终止错误。

步骤同时记录尝试次数、结构化错误代码、用户可读错误摘要、是否可重试、是否可跳过和更新时间。

### 4.2 自动重试

默认最多执行两次，即首次执行失败后自动重试一次。以下错误可自动重试：

- 网络超时或临时连接失败。
- 文献服务限流或短暂不可用。
- 模型服务临时错误。
- browser-worker 临时抓取失败。

数据格式错误、缺少必要输入、代码安全校验失败和确定性业务校验失败不自动重试。它们直接进入等待处理或终止状态，并在对话区说明需要修改的内容。

### 4.3 重新执行与跳过

- 重新执行仅重置目标步骤及依赖其输出的后续未完成步骤。
- 已完成且不依赖失败产物的步骤不重复执行。
- 只有非关键步骤开放跳过。
- 跳过影响可信度时，运行状态记录可信等级降级原因，最终报告写入限制与溯源信息。
- baseline、实验结果和报告生成等关键步骤默认不可无痕跳过。

### 4.4 历史任务恢复

历史任务接口返回运行状态、最后活动时间、当前或最后失败步骤、是否可恢复和简要进度。用户选择任务后：

- 前端重新获取完整运行快照。
- 已完成步骤保持完成状态。
- 因进程中断遗留的 `running` 步骤转换为可重试状态。
- 任务定位到最后未完成、等待处理或失败的步骤。
- 恢复动作写入运行历史，保证审计可追踪。

## 5. 数据流

### 5.1 新任务

1. 用户在左栏提交研究任务。
2. 前端创建运行，并附加 baseline 或实验辅助输入。
3. 前端直接启动运行。
4. 前端轮询运行快照并更新对话消息、阶段状态和结果面板。
5. 失败步骤按错误类型自动重试一次或进入等待处理。
6. 工作流完成后展示报告、可信度和导出入口。

### 5.2 文献预览

1. 用户在中栏选择文献。
2. 前端检查论文 PDF 地址。
3. 有 PDF 时直接显示；没有时调用预览接口。
4. 后端复用 browser-worker 抓取并缓存结果。
5. 右栏展示快照、元数据、状态和原始链接。

### 5.3 实验重设计循环

1. 代码实验完成并生成比较结果。
2. 结果门判断性能是否明显较差。
3. 较差结果进入实验重设计，增加循环轮次并更新实验方案。
4. 新方案再次进入代码实验。
5. 达到通过条件或轮次上限后进入结果解释与报告。

前端在同一阶段内展示每轮方案、结果和进入下一轮的原因。

## 6. 错误与可信度规则

- 前端不依据超时自行推断后端失败，以后端步骤状态为准。
- 后端错误返回稳定的错误代码和可读摘要，不把内部堆栈直接展示给用户。
- 自动重试、人工重试、跳过和恢复均写入步骤历史。
- 文献抓取失败不等于文献核验失败；两者使用独立状态。
- 网页快照只用于原文阅读辅助，不自动提升引用可信度。
- 主流程不得重新启用从论文链接或代码链接自动寻找 baseline。
- AI 生成 baseline 必须标记为本地演示基线，不得表述为外部复现结果。
- 实验循环达到上限仍表现较差时，报告必须保留负面结果和限制，不生成虚假的改进结论。

## 7. 验证标准

### 7.1 后端测试

- 可恢复错误首次失败后自动重试一次。
- 第二次失败进入 `waiting_action`。
- 不可恢复错误不会自动重试。
- 重新执行只影响正确的步骤范围。
- 非关键步骤可跳过，关键步骤不可跳过。
- 中断的运行能够恢复，已完成步骤不重复执行。
- 恢复、重试和跳过均保留审计记录。
- 文献预览能够在 PDF、网页快照和元数据兜底间正确路由。
- baseline 来源规则和实验重设计循环保持有效。

### 7.2 前端验证

- 宽屏三栏和窄屏折叠布局正确。
- 对话提交能够直接创建并启动任务。
- 对话消息和中栏步骤状态与后端一致。
- `waiting_action` 状态显示正确的重试和跳过按钮。
- 用户可以从历史列表选择并恢复任务。
- 点击文献可切换右侧 PDF 或网页快照。
- 实验重设计轮次可见。
- TypeScript 类型检查和生产构建通过。

### 7.3 集成验证

- 后端自动化测试通过。
- 前端生产构建通过。
- Docker 中 frontend、backend 和 browser-worker 健康检查通过。
- 完成一次端到端任务，覆盖文献选择、原文预览、baseline 接入、实验运行和报告生成。
- 通过可控故障验证一次自动重试和一次历史任务恢复。

## 8. 范围边界

本轮不包含：

- 引入 Celery、Redis 或其他外部任务队列。
- 将轮询全面替换为 SSE 或 WebSocket。
- 多用户账户、权限和云端同步。
- 对现有科研 Agent 进行无关重写。
- 恢复自动 baseline 搜索主路径。

这些能力可以在运行控制接口稳定后作为后续版本扩展。

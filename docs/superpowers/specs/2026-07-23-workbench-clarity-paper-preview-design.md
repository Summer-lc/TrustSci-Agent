# 工作台清晰度与文献预览优化设计

## 目标

降低三栏工作台的视觉负担，确保可信 Baseline 内容完整显示，并避免论文预览自动进入耗时的人机验证页面。

## 已确认根因

1. `BaselineIntakePanel` 位于 12 列网格中但没有列跨度，只占 1 列，导致表单与说明文字严重压缩。
2. 文献被选中后，`Workbench` 会自动请求网页快照；浏览器导航超时为 45 秒，后端请求超时为 90 秒。
3. 浏览器服务没有识别 Cloudflare 等人机验证页，`Just a moment...` 页面仍会被截图并返回。
4. 中央工作区连续展示标题、三格状态条、完整参赛准备度和六张大流程卡，信息层级重复。

## 设计

### 信息层级

- 保留三栏结构和六阶段主流程。
- 参赛准备度改为可展开摘要，默认仅显示分数、状态和一句结论。
- 流程导航改为紧凑横向步骤条；仅当前阶段显示说明，其他阶段只保留序号、名称和状态。
- 不新增全局卡片，阶段内容仍一次只显示一个阶段。

### Baseline 阶段

- Baseline 输入和可信结果均改为全宽卡片，按“来源设置 → 可信结果”纵向排列。
- 长文本、链接、限制说明和指标允许换行，不使用省略号或固定高度截断。
- 旧的自动发现入口继续折叠，仅作为兼容调试功能。

### 文献阅读

- 优先使用明确的 PDF 地址；arXiv 标识自动转换为直接 PDF 地址。
- 没有安全直达 PDF 时，仅显示文献元数据、摘要和原文链接，不自动启动浏览器抓取。
- 网页快照改为用户主动触发的备用操作。
- 浏览器抓取缩短等待时间，并识别人机验证页；命中后不展示验证截图，返回“请打开原文”的明确提示。
- 人机验证结果也进入缓存，避免重复等待同一失败页面。

## 验收标准

- Baseline 表单和结果在桌面与窄屏下均无横向截断，长文本可完整阅读。
- 中央顶部默认高度明显降低，六阶段仍可直接切换。
- 切换到没有 PDF 的文献时不发生自动网页抓取。
- Cloudflare/验证码页面返回元数据降级提示，不返回截图。
- 前后端测试、类型检查、生产构建和浏览器视觉检查通过。

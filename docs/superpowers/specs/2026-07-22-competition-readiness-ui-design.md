# 参赛准备度与工作台视觉优化设计

## 目标

在不改变现有三栏科研工作台和后端流程的前提下，让用户一眼区分“系统已运行”和“结果可用于参赛”，并改善桌面端、窄屏和移动端的信息层级。

## 方案选择

- 方案 A：只调整颜色、圆角和留白。改动小，但无法解决演示数据被误认为真实结果的问题。
- 方案 B：重做成独立仪表盘。视觉变化明显，但会打断现有对话、流程、文献三栏操作路径。
- 方案 C（采用）：保留三栏结构，新增参赛准备度与数据可信提示，并重塑关键区域的视觉层级。

## 信息架构

中央工作区顶部由三部分组成：

1. 任务标题和当前状态，保留现有运行阶段信息。
2. 参赛准备度卡片，展示百炼连接、数据真实性、有效引用、实际实验和标准报告五项检查。
3. 六阶段流程导航，使用紧凑流程带表达完成、运行、待处理和循环状态。

准备度仅基于后端已有事实计算，不生成新的科研结论：

- 百炼：`config.llm_enabled`。
- 数据真实性：数据名称、来源、备注及地震数据集名称中出现 `demo`、`synthetic`、`sample` 等词时判为演示数据；没有数据时判为未准备。
- 引用：至少有一篇 `report_eligible` 论文；三篇以上视为较充分。
- 实验：代码实验验收门全部通过，且结果不是 `failed`；若只有实验辅助数据则显示为人工结果待核验。
- 报告：存在正式报告，且 Claim Audit 没有不支持结论。

总状态分为：

- `ready`：可进入参赛材料整理。
- `warning`：流程可演示，但仍有可信性或材料缺口。
- `blocked`：缺少百炼、真实数据、实验或报告等关键环节。

## 视觉设计

- 页面底色使用浅灰蓝，卡片为白色，主色为科研蓝，可信通过使用低饱和绿色，风险使用琥珀色。
- 左栏保持白色但增加轻微层次，中央栏承担主要任务，文献栏维持安静阅读背景。
- 顶部状态区采用低密度卡片而非大面积彩色块，避免抢占实验与报告内容。
- 六阶段导航在宽屏单行展示，中屏三列，移动端两列；循环信息保留琥珀色提示。
- 所有状态不仅依赖颜色，同时提供文字和图标。

## 错误与可信边界

- 演示或合成数据永远不能显示为“真实数据”。
- AI 生成 baseline 不等于外部复现结果。
- 没有有效引用、没有实际实验或 Claim Audit 有不支持项时，界面不能显示“可提交”。
- 后端字段缺失时采用保守判断，显示“待核验”而非默认通过。

## 测试与验收

- 纯函数测试覆盖：空任务、合成数据、真实数据、有效引用、通过实验、报告风险和完整闭环。
- 前端 TypeScript、Vitest 和生产构建必须通过。
- 浏览器检查 1600px 桌面、约 1100px 窄屏和移动布局，无横向溢出、遮挡或不可读状态。
